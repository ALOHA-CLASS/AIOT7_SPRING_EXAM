| 항목 | 내용 |
|------|------|
| 교과목 | 웹 애플리케이션 개발 |
| 평가일시 | 2026.10.15 (목요일) |
| 평가방식 | 평가자 체크리스트 (답안지 작성) |
| 문항 / 배점 | 5문항 × 20점 = 100점 |
| 평가 범위 | Spring Boot, Spring MVC, Spring Data JPA, REST API |
| 프로젝트 | `exam` - 할일 관리(Todo) 애플리케이션 스켈레톤 |

## 1. 시험 개요

수업에서 사용한 Spring Boot 프로젝트를 기반으로 만든 **할일 관리(Todo)** 스켈레톤 코드가 제공됩니다.
코드 곳곳에 `[문제 N-①]` 형태의 **빈칸**이 있으며, 빈칸에 들어갈 **어노테이션 / 메소드 / 객체 / 테이블 정의**를
평가 문서 **[평가] 웹 애플리케이션 개발.hwp** 의 답안란에 작성하여 제출합니다.

- 답안은 평가 문서(hwp)의 답안란에 **자필로 작성**합니다.
- 프로젝트에서 직접 코드를 채우고 실행하여 **답을 확인해 보는 것은 선택**입니다. (제출물은 답안지입니다.)

## 4. 빈칸 찾는 방법

소스에서 아래와 같은 주석을 검색하면 문제의 빈칸 위치를 찾을 수 있습니다.

```java
/* [문제 1-①] 이 클래스를 JPA 엔티티로 선언하는 어노테이션을 작성하시오. */
```

- 빈칸 위치에는 코드 대신 `/* [문제 N-번호] ... */` 주석이 있고, 주석에 **무엇을 작성해야 하는지** 설명되어 있습니다.
- 답안지의 문제에는 같은 코드가 `[①]`, `[②]` ... 로 표시되어 있습니다. 번호가 서로 대응됩니다.
- 코드를 채울 때는 빈칸 주석을 지우고 그 자리에 작성하면 됩니다. 필요한 `import` 는 이미 포함되어 있습니다.

## 5. 도메인 요약 (참고)

### 5.1 상태 `TodoStatus`

| 값 | 설명 |
|----|------|
| `TODO` | 할 일 (기본값) |
| `DOING` | 진행 중 |
| `DONE` | 완료 |

### 5.2 공통 필드 `Base` (모든 엔티티가 상속)

| 필드 | 설명 |
|------|------|
| `no` | PK, 자동 증가(IDENTITY) |
| `id` | UUID 문자열, UNIQUE / NOT NULL |
| `createdAt`, `updatedAt` | 생성일 / 수정일 |

### 5.3 `Todo` 엔티티 필드

| 필드 | 타입 | 조건 |
|------|------|------|
| `title` | String | NULL 불가, 최대 100자 |
| `content` | String | 최대 1000자 |
| `status` | TodoStatus | enum 이름을 문자열로 저장, NULL 불가, 최대 20자 |
| `priority` | Integer | 1(높음) ~ 3(낮음) |
| `dueDate` | LocalDate | 마감일 |

### 5.4 계층 구조

```
브라우저 ─> Controller(MVC) / Api(REST) ─> Service ─> Repository ─> DB(H2)
```

## 6. 기능 명세

### 6.1 REST API (`TodoApi`, `/api/todos`)

| 기능 | 메소드 / 경로 | 응답 |
|------|---------------|------|
| 목록 조회 | `GET /api/todos?status=TODO` | 200, JSON 목록 |
| 제목 검색 | `GET /api/todos/search?keyword=구현` | 200, 우선순위 오름차순 |
| 마감 지난 미완료 | `GET /api/todos/overdue` | 200 |
| 상태별 개수 | `GET /api/todos/count?status=DONE` | 200, 숫자 |
| 단건 조회 | `GET /api/todos/{no}` | 200 / 없으면 404 |
| 등록 | `POST /api/todos` (JSON) | **201 Created** |
| 수정 | `PUT /api/todos/{no}` (JSON) | 200 |
| 상태 변경 | `PATCH /api/todos/{no}/status?status=DONE` | 200 |
| 삭제 | `DELETE /api/todos/{no}` | **204 No Content** |

### 6.2 화면 (`TodoController`, `/todos`)

| 화면 | 메소드 / 경로 | 뷰 |
|------|---------------|----|
| 목록 | `GET /todos?status=TODO` | `todo/list` |
| 등록 폼 | `GET /todos/new` | `todo/form` |
| 등록 처리 | `POST /todos` → redirect `/todos` | - |
| 수정 폼 | `GET /todos/{no}/edit` | `todo/form` |
| 수정 처리 | `POST /todos/{no}` → redirect `/todos` | - |
| 삭제 처리 | `POST /todos/{no}/delete` → redirect `/todos` | - |

## 7. (선택) 실행 및 확인 방법

> 프로젝트 루트(`exam`)에서 실행합니다. Windows 는 `gradlew.bat`, 그 외는 `./gradlew` 를 사용합니다.

```bash
# 테스트로 답안 확인
gradlew.bat test

# 애플리케이션 실행 후 http://localhost:8080 접속
gradlew.bat bootRun
```

- `TodoServiceImpl` 은 문제 2의 Repository 메소드(`findByStatus` 등)를 호출합니다.
  따라서 **문제 2를 완성하기 전에는 컴파일 오류가 발생하는 것이 정상**입니다. (오류 메시지가 힌트가 됩니다.)
- 5개 문제를 모두 올바르게 완성하면 `ExamTests` 의 모든 테스트가 통과하고 화면/API 가 동작합니다.

| 테스트 | 확인하는 문제 |
|--------|---------------|
| `문제1 - todo 테이블 컬럼 정의` | 문제 1 |
| `문제2 - 상태별 조회 / 개수`, `제목 검색`, `JPQL 마감 지난 미완료 목록` | 문제 2 |
| `문제3 - 등록 시 기본 상태 TODO, 수정(변경 감지), 삭제` | 문제 3 |
| `문제4 - 목록 화면`, `등록 처리 후 redirect`, `수정 화면` | 문제 4 |
| `문제5 - POST 201 / PATCH / DELETE 204 / 404` | 문제 5 |

## 8. 유의사항

- 수정하지 않는 파일: `Base.java`, `TodoStatus.java`, `TodoService.java`, `ExamTests.java`, `templates/`, `data.sql`, `build.gradle`
- 답안은 답안지에 작성한 내용만 채점합니다. 프로젝트 소스 수정 여부는 채점에 반영되지 않습니다.
- 제출 시간을 엄수하세요. (제출기간 이후 제출은 미제출 인정, 제출기간 경과 후 제출 시 패널티 -5점)
- 참고 자료 및 외부 도구 사용 범위는 평가자의 안내에 따릅니다.
